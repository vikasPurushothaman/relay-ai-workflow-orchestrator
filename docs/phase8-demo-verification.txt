Defects and findings
--------------------
D-8.6-1 (fixed, code + regression tests): console approve/reject/cancel returned 403
  when the dev console is opened at the documented http://127.0.0.1:5173, because
  the Vite proxy forwards that Origin and the API default allowed only
  http://localhost:5173. Probe with a nonexistent approval through the proxy:
  before 127.0.0.1:5173 -> 403, localhost:5173 -> 404; after 127.0.0.1:5173 -> 404,
  localhost:5173 -> 404, 127.0.0.1:5174 -> 403. Fix: default
  RELAY_ALLOWED_ORIGINS = http://localhost:5173,http://127.0.0.1:5173
  (ManagementCors.DEFAULT_ORIGINS). Tests: ManagementSecurityTest (both origins,
  POST + preflight; other port still 403), ManagementCorsTest (default parses to
  exactly two origins). Red first: only the 127.0.0.1 case failed.
D-8.6-2 (fixed, code + regression tests): the harness rebuilt the jar in place
  while the worker ran from it; the worker's dispatch loop died from an escaping
  Throwable and the process stayed alive and idle with no log (thread dump: idle
  dispatcher, no HTTP threads). Its shutdown log later showed
  java.lang.NoClassDefFoundError: org/springframework/util/ConcurrentReferenceHashMap$Values.
  Fix: WorkerLifecycle logs "Worker dispatch loop stopped unexpectedly" and exits
  with status 1; lease recovery resumes the work. Tests: WorkerLifecycleTest
  (Error -> fatal-exit hook once; RuntimeException -> keeps polling; stop() -> no
  hook). Red first: the Error case failed. README now says to stop the API and
  worker before rebuilding, with a troubleshooting row.
F1-F6 (DEMO.md wording, fixed): runs show "queued" right after a trigger (wait
  and re-run); use in-app navigation (a URL or reload clears the token); repeat
  approval only via the API (decided items leave the inbox); add `echo` after the
  world reset; outage drill may show one or two failed attempts; schema drill
  needs a port override if 9001 is taken. The corrected reset block was re-run.
